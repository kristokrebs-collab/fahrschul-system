# voiceovers/

Real narration audio for each pilot, generated via the Higgsfield MCP
connector's `generate_audio` (model `seed_audio`, voice **Arthur**,
`voice_id 30fc8796-ceb6-4a66-b3a7-4a145ef7f346`) — no ElevenLabs signup
needed, paid from the user's existing Higgsfield credit balance instead of
the Anthropic API.

## Why this exists / how it was built

Each pilot's script was split at its 10 section boundaries (Cold Open,
Promise, Setup, ... Payoff — see `pilots/*/script.md`), since `seed_audio`
caps a single generation at 2048 characters. Each section was generated
separately via `generate_audio_batch`, which also gives real per-section
speech durations. Those real durations were then used to **re-time each
pilot's `storyboard.json`**: the original hand-authored scene timings
(based on the script's target runtime) turned out to run considerably
faster than planned once actually spoken — e.g. Pilot 1 was planned at
9:50 but the real narration is 7:11. `storyboard-planned.json` in each
pilot folder keeps the original, pre-audio timing for reference.

## `<pilot-id>/segments-manifest.json`

One per pilot: the 10 segment audio URLs (Higgsfield's CDN), each one's
real duration, and the voice/model used. Generated by the same process
that re-timed the storyboards.

## The audio bytes themselves are not in this repo

The sandbox that generated this couldn't download from Higgsfield's asset
CDN (`d8j0ntlcm91z4.cloudfront.net`) — its egress policy returned a 403 on
that host (see `/root/.ccr/README.md` in that environment: "destination
host is not allowed... report the blocked host, don't route around it").
Durations were obtained through the API without needing the file bytes, so
the storyboards are correctly re-timed regardless — but assembling the
actual narration track has to happen somewhere with normal internet
access, which is almost certainly wherever you're reading this.

## Finishing it yourself

```bash
cd voiceovers
node mux-narration.js pilot-01-cancel-subscriptions
node mux-narration.js pilot-02-sleep-deprivation
node mux-narration.js pilot-03-supermarket-psychology
```

This downloads the 10 segments, concatenates them (ffmpeg concat, no
re-encoding — the segments are already the right order and format), and
muxes the result onto that pilot's rendered video in `../renders/`,
producing `<video_id>-final.mp4`. Requires a normal `ffmpeg` on PATH (a
full build, not a minimal capture-only one).

Segment URLs are signed/hosted by Higgsfield and may expire eventually —
if `mux-narration.js` gets 403/404s on the audio URLs, the segments need
regenerating (same prompts are in `segments-manifest.json` and the
per-pilot `script.md`, same voice ID above) rather than re-downloading.
