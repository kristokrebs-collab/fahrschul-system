# n8n — The Invisible Why pipeline

Two workflows:

- `youtube-pipeline.workflow.json` — the full production pipeline (research
  → score → research dossier → script → fact-check → language edit → human
  sign-off → title/thumbnail → storyboard → voiceover → render → QA →
  private upload). Generated by `generate-workflow.js` — see that file's
  header before hand-editing the JSON.
- `analytics-report.workflow.json` — weekly YouTube Analytics snapshot +
  Slack summary.

## Requirement: self-hosted n8n with filesystem access

This pipeline is filesystem-based (research dossiers, scripts, storyboards
all live as files in this repo, per the folder structure in the top-level
`README.md`). That means:

- **n8n Cloud will not work** for the Code-node steps (no arbitrary
  filesystem access). You need **self-hosted n8n** (Docker is easiest) with
  this repository's `youtube-invisible-why/` folder mounted into the
  container, e.g.:

  ```bash
  docker run -it --rm \
    -p 5678:5678 \
    -e NODE_FUNCTION_ALLOW_BUILTIN=fs,path \
    -e INVISIBLE_WHY_ROOT=/data/youtube-invisible-why \
    -v ~/.n8n:/home/node/.n8n \
    -v /absolute/path/to/youtube-invisible-why:/data/youtube-invisible-why \
    n8nio/n8n
  ```

- `NODE_FUNCTION_ALLOW_BUILTIN=fs,path` is required — n8n's Code node
  sandboxes Node's built-in modules by default, and every agent-call node
  in this pipeline reads a prompt file and writes an output file directly.
- `INVISIBLE_WHY_ROOT` must point at the mounted `youtube-invisible-why/`
  folder inside the container.

## Credentials to create in n8n (Settings → Credentials)

| Credential name (must match exactly) | Type | Used by |
|---|---|---|
| `Anthropic API Key` | Header Auth (`x-api-key: <your key>`) | every "Call Claude" node |
| `ElevenLabs API Key` | Header Auth (`xi-api-key: <your key>`) | Generate Voiceover node |
| `SerpApi Key` | Query Auth (`api_key`) | Collect Google Trends Signal (optional — node has `continueOnFail`, pipeline works without it) |
| `YouTube OAuth2 (Invisible Why channel)` | YouTube OAuth2 | Upload to YouTube (Private), Fetch YouTube Analytics — needs `youtube.upload`, `youtube.readonly`, and `yt-analytics.readonly` scopes |

## Environment variables

| Variable | Purpose |
|---|---|
| `INVISIBLE_WHY_ROOT` | absolute path to `youtube-invisible-why/` inside the n8n container |
| `YOUTUBE_API_KEY` | YouTube Data API key for the (optional) competitor-upload signal node |
| `ELEVENLABS_VOICE_ID` | the voice ID you create per `docs/SETUP.md` §ElevenLabs |
| `SLACK_WEBHOOK_URL` | Slack incoming webhook for review/analytics notifications (swap for email/Telegram if you prefer — those nodes are single, easy to replace) |

## Import steps

1. Start n8n as above, open `http://localhost:5678`.
2. Workflows → Import from File → select `youtube-pipeline.workflow.json`.
3. Create the 4 credentials above, then open each `httpRequest`/`youTube`
   node that references a credential and re-select it from the dropdown —
   the JSON ships with placeholder credential IDs (`REPLACE_ME`) since
   credential IDs are per-instance and can't be pre-filled.
4. Repeat import for `analytics-report.workflow.json`.
5. **This JSON was authored to n8n's 1.x schema but not test-imported
   against a live instance** (none was available while building this). Walk
   each node once after import — if your n8n version renamed an HTTP
   Request or Code node parameter, the node will show a small warning
   badge; the fix is almost always re-picking the same option from a
   dropdown, not restructuring the node. The node order, connections, and
   all JS logic are the real deliverable and don't depend on n8n version.
6. Before the first real run, do a manual test with `Execute Node` on
   "Weekly Research Trigger" → step through node by node rather than
   running the whole pipeline live end to end, since a mistake before the
   private-upload step is cheap and after it isn't.

## Regenerating the main pipeline

If you add/remove an agent or change the branching logic, edit
`generate-workflow.js` (data-driven — see the `AGENT_STEPS`-style
`agentStep()` calls) and re-run `node generate-workflow.js`. It self-
validates (no orphan nodes, no dangling connections, no duplicate names)
before writing the file, so a bad edit fails at generation time instead of
silently producing a broken import.
