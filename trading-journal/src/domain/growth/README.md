# `src/domain/growth` – Wachstum: Ziele, Challenges, Gewohnheiten, Serien, Bestleistungen, Skills (P08)

Pure TypeScript (no React), deterministic, `now` injected. Growth is measured on the **process** – discipline,
journaling, rule-keeping, routines – and **never** on P&L or a trade count: a trade count is only ever an upper limit,
a challenge never needs a trade to be won, records and levels are process records. Outcome metrics (win rate, PF, R)
can exist as goals (a mentor may set one) but are never celebrated.

Everything reuses what the journal already computes: the coach's behaviour events (`@/domain/coach`, P04), the
discipline days / streak (`@/domain/insights/discipline`), the reports' goal measurement (`goalActual`,
`@/domain/reports`), the P05 limits (discipline limits, `riskSpread`) and the check-in (`@/domain/psych`).

| File | What |
|---|---|
| `goals.ts` | **Wave-0 contract** `GoalDraft` / `Goal` / `addGoalFromDraft(draft)` (signatures final). `sanitizeGoalDraft` (a trade count and the limit metrics are forced to `atMost`, rates clamped 0–1, outcome metrics get `kind: "outcome"`, behaviour / habit goals need their scope), `goalOf`, `holdOf` (periods in a row: `HOLD_DEFAULT` day 5 · week 4 · month 3 · quarter / year 1, or `goal.hold`), `sameGoal`, `withGoalAppended`, `activeGoalsOf`. `addGoalFromDraft` writes `settings.growth.goals` through the journal store (lazy import – the domain keeps no static store edge; `setGoalStore` for tests), de-duplicates an active goal and is **serialised**, so the coach's "Plan übernehmen" handing over three goals at once never loses one. Extension fields: `hold`, `log` (self-check of `custom` goals per period key). |
| `model.ts` | `settings.growth` (passthrough, synced, `merge3` merges every list per `id`): `goals`, `challenges`, `habits`. `growthOf(settings)` (sanitised, unknown keys kept), `withGrowthItem`, `withGrowthPatch` (same object when the id is missing), `activeHabits`, `AUTO_HABITS` (`auto:checkin`, `auto:plan`, `auto:review` – read the day journal), `HABIT_SUGGESTIONS`. Items are never hard-deleted: goals → `dropped`, challenges → `dropped`, habits → `archived`. |
| `context.ts` | `prepare(ctx)` → `Prepared`: trades by entry, closed, per day (`dayKeyOf`), traded days, discipline days, limits, events per day, today. `prepareAt(ctx, at)` = the journal as it was at `at` (level-up comparison). |
| `habits.ts` | `habitDone` (manual: `checkin.habits[id]`; automatic: check-in / plan / review or note), `habitStreak` (today open does not break it), `habitBest`, `habitRate`, `habitGrid(habits, days, todayKey, weeks)` (ISO weeks, Monday first, future cells marked), `addDays`. |
| `streaks.ts` | `streakBoard(p)`: **journal** (trading days with every closed trade reviewed or a day note / check-in), **check-in** (calendar days, a weekend without one pauses), **green** (= trading days *in the limits*: day loss and trades per account within the discipline limits, no rule violation / overtrading / revenge / tilt – a red day that kept the limits is green; a breach today breaks it at once), **discipline** (`disciplineStreak`, reused). `journalDayOk`, `greenDayOk`, `checkinStreak`, `tradeRun`. |
| `progress.ts` | `goalProgress(goal, p, habits)`: value of the current period (`goalValue` = `goalActual` on the scoped trades of the period, the habit rate, or the self-check), ring ratio (an `atMost` limit fills with the elapsed share of its period while it holds), state `met · onTrack · atRisk · missed · noData`, history of complete periods, **streak since the goal was set** (periods without data skipped), `achieved` (streak ≥ hold), milestones (1…hold, or quarters of it), `celebrate` (false for outcome goals), `overdue`. `rankGoals`, `weekSummary`, `goalValueText`, `periodUnit`. |
| `challenges.ts` | `CHALLENGES` (8 templates: Ruhige Hand, Kein Hinterherlaufen, Stop immer, Regeltreu, Im Limit, Review-Woche – *clean*: won when the days pass without a violation; Check-in-Woche, Plan-Woche – *count*: 5 of 7 days). `challengeProgress(c, p)` → day, cells (ok / fail / pending / future / idle), violations with the trade, state `active · done · failed`. `suggestChallenges(trackers, running, checkinStreak)` – the deck's first card matches the trader's most frequent pattern. |
| `bests.ts` | `personalBests(p)` – process records only: longest journal / check-in / green / discipline streak, trades without a rule violation, trades in a row with a review, best discipline month (≥ 5 scored days); `live` = the running run IS the record. `milestones(p, prefs)` (ladders: check-ins, reviews, discipline, green days, challenges, goals) and `nextMilestones` (per ladder only its next step, closest first). |
| `skills.ts` | `skillProfile(p)`: six axes 0–100 – Disziplin, Risiko (the coach's "Risiko-Konstanz" formula on P05 `riskSpread`), Journaling, Geduld, Emotionen, Planung – each with its sample and a minimum; level 1–5 (`LEVEL_NAMES`: Einstieg · Aufbau · Solide · Stark · Meister), 0 = zu wenig Daten; overall Ø from ≥ 3 axes. |
| `charts.ts` | `progressSeries(p, habits, weeks)` – per ISO week Ø discipline, journal rate, check-in days, rule breaks, habit rate (`null` = no data, never a fake zero); `seriesTrend`. |
